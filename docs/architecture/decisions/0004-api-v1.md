# ADR 0004: Versioned API V1

- Status: Accepted
- Date: 2026-08-02

## Context

Current unversioned routes are used by the local product and cannot be broken,
while persisted enterprise workflows need a stable compatibility boundary.

## Decision

Preserve current routes and expose Product V1 compatibility under `/api/v1`.
Versioned responses use request identifiers, stable error envelopes, UTC
timestamps, validation, bounded pagination, and authorization. Routers expose
domain resources rather than database tables. See [API V1](../api-v1.md).

## Consequences

Existing clients continue to work. New integrations have an explicit contract,
but fixes may need coverage on both compatibility paths until clients migrate.

## Alternatives

- Replacing all existing routes was rejected as a breaking migration.
- URL-less header versioning was rejected as less inspectable for this product.

## Implementation status

Contract-ready. OpenAPI and `check:api-contracts` are the executable boundary;
verification results are recorded separately.

## Deferred work

API gateways, externally published SDKs, partner credentials, and a V2 policy
are deferred.
